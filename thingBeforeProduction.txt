Production-Readiness Audit — CarMarket Ghana

Overall verdict: Solid feature-complete MVP with a good foundation (zod validation, helmet, rate limiting, hashed reset tokens, Paystack signature verification, route-level code splitting). But there are 4 critical issues that must be fixed before any public deployment, including one that means your secrets are already compromised.

---

🚨 Critical — fix before anything else

1. Your secrets are in git (and on GitHub)

backend/.env is tracked and committed (git ls-files confirms it, last touched in commit fb74409). It contains JWT_SECRET, PAYSTACK_SECRET_KEY, SMTP_PASS, DATABASE_URL. There is no .gitignore at the repo root at all — 13,213 node_modules files, your uploads/ folder, and backend/.env are all in git history on GitHub.

What to do, in order:
1. Rotate every secret: new JWT_SECRET, new Paystack keys (dashboard), new SMTP password, new DB password.
2. Create a root .gitignore: .env, node_modules/, uploads/, dist/, scratch/.
3. Remove the files from the index (git rm --cached) and commit — but history still has them, so rotating is non-negotiable. Optionally run git filter-repo / BFG to scrub history, then force-push.
4. Commit .env.example files with keys but no values.

2. Password reset returns the token in the API response

authController.js:303 — if SMTP isn't configured, forgot-password reploy without SMTP env vars and anyone can reset any account'spassword, including the admin's (full takeover). Gate this behind NODE_ENV !== 'production' explicitly, or remove it.

3. CORS is fully open, with credentials

index.js:31-36 — callback(null, true) allows every origin and sets credentials: true. Replace with an allowlist: FRONTEND_URL plus localhost in dev. This also pairs
with moving auth to cookies (see security section).

4. Stored XSS via user "images"

imageController.js:49-51 serves user-supplied SVG as image/svg+xml P disabled (index.js:24). SVG can carry <script> — a seller uploadsone, victims open the listing, script runs with their localStorage JWT available. Fix: reject SVG server-side (validate the base64 MIME type against jpg/png/webp
only), or serve with Content-Security-Policy: sandbox + Content-Dise handler also 301-redirects to arbitrary URLs(imageController.js:56-61) — an open redirect; restrict to your own /uploads path.

5. JWT fallback secret

authMiddleware.js:16 — jwt.verify(token, process.env.JWT_SECRET || 'fallback_secret'). You already hard-fail at boot on missing JWT_SECRET (index.js:12-18), so
delete the fallback — a typo'd env name currently silently accepts

Security measures to take

Auth & sessions
- JWT lives 7 days in localStorage, no refresh token, no revocation, and logout is a server-side no-op (authController.js:338-340). Move to short-lived access tokens
  (15m) + httpOnly Secure SameSite=strict refresh cookies; store a ord reset / role changes invalidate old sessions (right nowresetting a password doesn't kick out existing sessions).
- Add a response interceptor in frontend/src/utils/api.js (currentl that logs out and redirects to /login on 401 — today an expiredtoken leaves every page silently broken.
- Bump bcrypt to 12 rounds (authController.js:47), and stop confirmregister (authController.js:44) — that's account enumeration.
- Standard registration never verifies email (emailVerified is only set via Google, authController.js:245) — send a verification mail before listings go public.
- Seed file creates admin@carmarket.com / Password123! (prisma/seedgainst prod; require an env-provided admin password.
- Frontend has no ProtectedRoute — guards are copy-pasted inline in 6 files, and both dashboards fetch privileged data before the role check
  (AdminDashboard.jsx:61-63, SellerDashboard.jsx:35-75). Centralize-fetch.

API & input
- express.json({ limit: '50mb' }) (index.js:57) is a DoS surface. Drop to ~2mb and move uploads to multipart (you already have multer).
- vehicleSchema images/documents have no size or count cap (validatPOST 16MB base64 blobs straight into MySQL MediumText rows, 15 timesover. Add z.string().max(...), max 15 images, and validate the data-URI prefix server-side.
- Multer's filter checks only extension + declared mimetype (uploadpoofed. Verify magic bytes (e.g. file-type package).
- Add length caps to message content, report reasons, and description (sendMessage, createReport currently unbounded); validate that receiverId/vehicleId exist;
  parseInt guards so bad IDs return 400 not 500.
- Return no internal error text in production: errorHandler.js:5-7 leaks err.message, and createVehicle/updateVehicle return raw error.message
  (vehicleController.js:163-164).

Payments
- Signature check uses !== (billingController.js:248) — use crypto.timingSafeEqual.
- Payment.amount is a Float (schema.prisma:259) — store pesewas as s (+0.001) will eventually bite.
- applyVerifiedPayment isn't race-safe — two concurrent webhook + verify calls can double-extend a subscription. Make it a transaction with a status guard
  (updateMany where status: PENDING).
- generateReference (plans.js) is 6 chars of Math.random() — use crypto.randomBytes; collisions hit a unique constraint.
- Ignore the client-supplied callbackUrl (billingController.js:177) env only.
- Admin verify/reject/delete have no audit log — add an AdminAction table; also deleteUser (adminController.js:153-167) doesn't clean up vehicles/favorites/messages
  and will throw FK errors, and doesn't prevent deleting admins.

Privacy / data exposure
- getVehicleById (vehicleController.js:319-345) is public with no status or expiry check — anyone can view PENDING/REJECTED/SOLD/expired listings by ID, and it leaks
  the seller's email plus document blobs. Filter to AVAILABLE + notns it or is admin; drop email from the public payload (you alreadyshow phone).
- Route-limiter bug with real impact: the comment at index.js:46 sa API limiter, but the limiter is mounted at /api/ before the imageroute, so all image loads count against 200 requests / 15 min per IP. One search page loads 12–24 images → anonymous users get locked out in minutes. Mount the
  image route before the limiter, or exempt it.
- Add app.set('trust proxy', 1) — you deploy behind ngrok/tunnels; without it, rate limiting keys on the proxy IP (everyone shares one bucket) and
  req.protocol/req.secure are wrong.
- DB indexes are missing for your hot queries: add composite indexes on Vehicle(status, createdAt), Vehicle(status, price), Vehicle(make, model), Vehicle(featured,
  status), Message(vehicleId, createdAt). Also: no prisma/migrationbeen using db push. Switch to prisma migrate + migrate deploy beforeprod, or you have no repeatable, reviewable schema changes.

Speed

Backend
1. Move images out of MySQL. Base64 in MediumText rows bloats the DB, inflates memory, and makes every query heavier. Put originals on S3/Cloudinary, store only URLs
   — this also gives you free thumbnails/variants (the frontend cur original everywhere).
2. Fix the image/rate-limiter ordering bug (above) — it's both a security item and your #1 perceived-latency killer.
3. Push plan-ranking sort into SQL (above); paginate admin endpointn/users, seller listings, favorites are all unpaginated).
4. Add Redis (or even an in-memory LRU) to cache /vehicles/featured and /vehicles for 30–60s — home and search are your hottest endpoints and they run 3–4 queries +
   JS sorting each hit.
5. Tune the Prisma pool (connection_limit) in db.js; log slow queries (PrismaClient({ log: ['warn','error'] })).

Frontend — mostly one-liners with big wins
1. loading="lazy" decoding="async" on images — zero hits in the cody downloads 12–24 full-size images per page.
2. AuthContext.jsx:78 — {!loading && children} unmounts the entire app until /auth/me resolves: every visitor gets a blank white first paint. Render children always;
   gate only protected routes.
3. SearchResults.jsx:88 — FilterContent is a component defined inside render, so the filter sidebar remounts on every keystroke and drops input focus. Hoist it out.
4. Self-host fonts (@fontsource) instead of render-blocking Google Set once images move to S3.
5. Cleanup: revoke URL.createObjectURL previews in SellCar (SellCar.jsx:147), clear the BillingCallback retry timer (BillingCallback.jsx:46-47), add AbortController
   to CarDetails/SearchResults to kill stale-response races.
6. The bundle itself is in good shape (route-level lazy loading + vendor chunks, ~350KB entry) — don't touch it.
